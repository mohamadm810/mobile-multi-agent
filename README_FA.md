# Mobile Multi-Agent — راهنمای راه‌اندازی با گوشی

این سامانه یک تیم برنامه‌ریزی چندایجنتی است که روی GitHub Actions اجرا می‌شود؛
برای اجرای چرخه نیازی به روشن بودن کامپیوتر شخصی نیست.

## قابلیت‌های نسخه اول
- هفت نقش متوالی: تحلیلگر نیازمندی، معمار، برنامه‌ریز توسعه، تستر، بازبین مستقل،
  مدیر مرکزی و مستندساز.
- اتصال Gemini از طریق GitHub Actions Secret.
- حافظه و گزارش در `workspace/STATE.json` و `workspace/REPORT.md`.
- اجرای دستی از گوشی و اجرای خودکار پس از تغییر درخواست.
- تست‌های خودکار بدون نیاز به کلید API.

## محدودیت هزینه
کد این پروژه رایگان و متن‌باز است؛ اما Gemini API و GitHub Actions سهمیه و محدودیت دارند.
رایگان/نامحدود بودن دائمی هیچ‌کدام تضمین نمی‌شود. مصرف این نسخه با هفت فراخوانی موفق مدل در هر چرخه انجام می‌شود؛ در صورت خطا، تلاش‌های مجدد و مدل جایگزین ممکن است تعداد درخواست‌ها را افزایش دهند. مدل اصلی و جایگزین در فایل گردش کار تنظیم شده‌اند.

## نصب از گوشی اندروید
1. فایل ZIP را استخراج کنید.
2. در GitHub مخزن `mohamadm810/mobile-multi-agent` را باز کنید.
3. همه محتویات پوشه `mobile_multi_agent` را در ریشه مخزن بارگذاری کنید
   (Add file → Upload files). اگر فایل‌های قبلی وجود دارند، قبل از جایگزینی diff را بررسی کنید.
4. در Settings → Secrets and variables → Actions → Secrets، مقدار
   `GEMINI_API_KEY` را به‌عنوان Repository Secret اضافه کنید.
5. مدل اصلی گردش کار `gemini-3.5-flash-lite` است تا اجرای رایگان و کم‌هزینه اولویت داشته باشد؛ در صورت خطای ظرفیت یا محدودیت موقت، مدل جایگزین `gemini-3.8-flash` امتحان می‌شود. نیازی به ساخت متغیر `GEMINI_MODEL` نیست. اگر متغیر قدیمی ساخته‌اید، آن را حذف کنید تا تنظیم گردش کار اعمال شود.
6. در Actions گردش کار `Run Multi-Agent` را باز کنید و Run workflow را بزنید.

## استفاده روزمره
- متن درخواست را در `workspace/REQUEST.md` بنویسید.
- اجرای `Run Multi-Agent` را از تب Actions آغاز کنید.
- گزارش را در `workspace/REPORT.md` و وضعیت را در `workspace/STATE.json` بخوانید.
- تصمیم‌های تأییدشده را به درخواست بعدی منتقل کنید.

## امنیت و مرز اختیارات
- کلید API فقط در Secret نگهداری شود؛ هرگز آن را در فایل‌ها، Issue یا گزارش وارد نکنید.
- نسخه اول فقط تحلیل و برنامه‌ریزی می‌کند. هیچ shell دلخواه، تغییر مخزن پروژه‌های دیگر،
  حذف فایل، انتشار یا deploy در اختیار مدل نیست.
- خروجی ایجنت‌ها پیشنهاد است و باید توسط انسان بازبینی شود.
- داده مشتری، اطلاعات شخصی و اسناد محرمانه را وارد درخواست نکنید.

## پایداری اتصال API
برای خطاهای موقت HTTP 429/500/502/503/504 و خطاهای موقت شبکه/timeout، هر مدل حداکثر سه بار با تأخیر افزایشی تلاش می‌شود. پس از اتمام تلاش‌ها، در خطاهای قابل‌بازیابی مدل جایگزین امتحان می‌شود؛ خطاهای دسترسی/درخواست مانند 400/403/404 بی‌درنگ گزارش می‌شوند. گزارش، مدل‌های تلاش‌شده را جدا از مدل‌هایی که پاسخ موفق داده‌اند ثبت می‌کند. وضعیت مدل در هر چرخه از نو تنظیم می‌شود تا داده اجرای قبلی وارد گزارش بعدی نشود. اگر ثبت گزارش در شاخه `main` پس از سه تلاش ناموفق بماند، فایل‌های گزارش و وضعیت به‌عنوان Artifact در GitHub Actions برای ۱۴ روز نگهداری می‌شوند.

## کیفیت گزارش چندایجنتی
هر نقش خروجی کوتاه و اختصاصی تولید می‌کند؛ فقط یافته‌های مرتبط نقش‌های قبلی به مراحل بعد منتقل می‌شود تا از تکرار متن و رشد بی‌رویه گزارش جلوگیری شود. خروجی ایجنت‌ها تحلیل مدل است و جایگزین بازبینی انسانی یا اجرای مستقل تست‌ها نیست. اگر اجرا شکست بخورد، وضعیت `failed` و خلاصه خطا در `workspace/STATE.json` ذخیره می‌شود؛ Workflow نیز این وضعیت را حتی در اجرای ناموفق به مخزن برمی‌گرداند.

## عیب‌یابی
- خطای `Missing GEMINI_API_KEY`: Secret با نام دقیق بالا تعریف نشده است.
- خطای HTTP 400/403/404: مدل انتخابی یا دسترسی API را در Google AI Studio بررسی کنید.
- خطای 429: محدودیت نرخ/سهمیه؛ بعداً دوباره اجرا کنید یا مدل/سهمیه حساب را بررسی کنید.
- اجرای ناموفق: Actions → اجرای مربوط → Job → Logs.
- اجرای تست‌ها بدون API: در Actions گردش کار `Tests` را اجرا کنید.

## توسعه نقش‌ها
برای افزودن نقش جدید، prompt آن را در `agent/roles.py` تعریف و مرحله آن را در
`agent/run.py` ثبت کنید. نقش جدید باید فقط خروجی متنی/تحلیلی تولید کند؛ افزودن ابزار اجرایی
نیازمند طراحی مجوز و تأیید انسانی جداگانه است.
